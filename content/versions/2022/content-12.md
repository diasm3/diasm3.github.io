## 2022-12-19 09:30:11
### 첫 번째 프로젝트를 마치고 나서…
첫 직장에서 첫 번째 프로젝트를 끝내고 나서 회고를 작성하지 못한 점이 아쉬워 간단히 느낀 점들을 적어보았습니다.

### 느낀 점
- 불정확한 지식으로 인해 숨겨진 오류가 발생했습니다.
- 겹겹이 쌓인 오류 산이 있었습니다.
- 환경변수를 설정하지 않아 발생한 오류는 찾기가 힘들었습니다.
- set-cookie를 사용할 때 동일 도메인 레벨에서만 저장이 가능하다는 점을 유의해야 합니다.
- 이메일 템플릿은 직접 작성해야 했습니다.
- raw query로 코딩했을 때 더 많은 것을 배웠습니다.
- Sequelize와 결과값이 유사하지만 실제로는 raw query로 최소한의 transaction으로 DB를 자유롭게 다룰 수 있었습니다.
- 에러 메시지를 주의 깊게 살펴야 합니다.
- ElasticBeanstalk는 매우 불편하게 느껴졌습니다.
- ElasticBeanstalk 설정 시 Docker build를 Docker Hub으로 사용해야 초기 빌드시 힙 메모리가 부족해 서버가 다운되지 않습니다.
- 백엔드는 node 버전에 따라서 크게 성능 차이가 없다는 것을 느꼈습니다.
- AWS Lambda는 생각보다 편리했습니다.
- AWS Cognito는 개선이 필요해 보였습니다. 마이그레이션 서비스도 없고 별도로 구성을 해야 하며, ID token 및 시스템을 이해해야 했습니다.
- Task 관리는 힘들었습니다.
- 요구 사항을 이해하고 그대로 구현했을 때 정확하지 않았습니다. (이해도 부족)
- Raw query에 대한 이해도가 낮아 어려움을 겪었습니다.
- 다른 사람이 작성한 코드를 즉시 이해하기가 힘들었습니다. 계속 열어보며 이해하려고 했습니다.
- 자신이 작업하고 배포하는 중에도 확신이 부족했습니다. 지속적인 오류로 인해 두려움이 생겼습니다.
- Kubernetes는 어렵게 느껴졌습니다.

1. tmux의 각 창의 세션은 독립적이라 각 창마다 토큰값을 갱신해야 합니다.
2. ElasticBeanstalk의 Cognito identity 권한을 주려면 STS 권한이 필요합니다.

### EB(ElasticBeanstalk) buffer size over 문제
EB에서 로드 밸런스 설정할 때 header의 buffer size가 제가 사용하고자 하는 사이즈보다 작아서 다음과 같은 문제가 발생했습니다. eb-cli를 사용하여 eb logs를 확인했더니 "upstream sent too big header"라는 메시지가 나왔습니다. 이 문제를 해결하기 위해 buffer size를 변경해야 합니다.

- 브라우저에서는 502 에러
- nginx 에러는 "upstream sent too big header while reading response header from upstream"입니다.

```bash
## 이런 폴더를 만들고 proxy.conf를 생성한 후
$ /project-folder/.platform/nginx/conf.d/elasticbeanstalk/proxy.conf

## 아래와 같이 내용을 입력한 후 eb-cli로 배포합니다.
$ vi proxy.conf
proxy_buffer_size                       16k;
proxy_buffers                           4 16k;

## 물론 eb-cli를 설치하고 env까지 다 설정해야 아래 명령어를 실행할 수 있습니다.
$ eb deploy
```
