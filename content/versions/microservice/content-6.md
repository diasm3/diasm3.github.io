# 진정한 마이크로서비스란?  
마이크로서비스는 소프트웨어 아키텍처 패턴으로, 복잡한 애플리케이션을 독립적인 서비스로 나누어 구성합니다. 각 서비스는 높은 퍼포먼스, 용이한 확장성, 그리고 편리한 유지보수라는 장점을 가집니다.  

TCP를 통해 데이터를 주고받기 때문에 언어에 구애받지 않고, 각 모듈은 원활하게 통합될 수 있습니다. 

Agile 개발 환경에서도 효과적으로 작동하며, 독립적으로 배포할 수 있습니다.

> 예를 들어, 쿠팡에서는 각 메뉴마다 별도의 팀이 있어 해당 모듈만 관리합니다. 이 모듈은 독립적으로 실행되어, 하나의 모듈에서 문제가 발생하더라도 전체 서버가 다운되는 경우는 없습니다.

## 마이크로서비스 도입 시 고려해야 할 사항  
- 우리 서비스에 적합한 방식인지?  
- 마이크로서비스 구현을 위해 얼마나 많은 코드가 필요한가?  
- 백엔드만으로 마이크로서비스를 구성한다면, 프론트엔드도 파편화가 가능한가?  
- 각 마이크로서비스의 레포지토리는 어떻게 관리해야 하는가?  
- 문서화는 어떻게 진행해야 하는가?  
- 이러한 복잡도를 감당할 수 있는가?  
- 애플리케이션의 파편화는 어느 정도가 적절한가?  

## 마이크로서비스의 5가지 장점  
1. **Decoupled Components**  
   - 다른 모듈과의 의존성이 없어 쉽게 변경 및 업데이트 가능  
2. **Scalability**  
   - 마이크로서비스는 메모리를 공유하지 않기 때문에 유연하게 스케일링 할 수 있음  
3. **Faster Development**  
   - 애플리케이션을 작은 단위로 분리하여 병렬적으로 모듈 개발 가능  
4. **Language and Technology Agnostic**  
   - 서로 다른 프레임워크나 언어를 사용할 수 있어 진입 장벽이 낮음  
5. **Reduced Complexity**  
   - 파편화에 의해 이해하기 쉬우며 보수, 테스트를 동시에 진행할 수 있음

# 마이크로서비스 구축을 위해 필요한 사항  
> 각 언어 및 프레임워크에서 지원하는 네트워크 방식을 사용하여 각 모듈을 연결합니다.

## NestJS에서 해야 할 것  
1. NestJS에서 제공하는 마이크로서비스 모듈을 활용하여 각 서비스에 적합한 프레임워크를 선택합니다. 예를 들어, REST API 시 RabbitMQ를 사용하는 것이 일반적입니다.  
   1. RabbitMQ  
   2. Kafka  
   3. MQTT  
   4. gRPC  
2. Kubernetes를 이용하여 각 마이크로서비스의 도커 이미지를 배포합니다.  

## Kubernetes에서 해야 할 것  
1. 각 Pod를 구성하여 서비스간의 통신을 관리합니다.  

## AWS에서 해야 할 것  
1. AWS 플랫폼을 활용한 마이크로서비스 배포를 위한 설정 및 관리.

## 목표  
> 각 Pods에 모듈을 배포하고, 통신이 정상적으로 이루어지는지 확인합니다.

1. TCP/IP를 사용하여 각 마이크로서비스 간의 요청-응답 데이터 통신을 진행합니다.  

## 앞으로의 계획  
1. Kubernetes 관련 학습 내용 정리  
2. NestJS의 마이크로서비스 관련 내용을 정리하고 레퍼런스 문서를 작성하여 AWS에 배포  
3. AWS 사용법 숙지  
4. 최종적으로 NestJS로 작성된 각 모듈을 컨테이너(Pods)에 배포하고 서비스를 운영합니다.
