# OAuth 란?
OAuth(Open Authorization)는 애플리케이션 간에 안전하게 인증 정보를 공유할 수 있게 해주는 인터페이스입니다. 2007년 12월에 OAuth 1.0이 출시되었고, 이후 구글은 2008년부터, 트위터는 서드파티 애플리케이션에서도 사용하도록 지원하기 시작했습니다. 

그러나 OAuth 1.0은 보안 구성을 위해 복잡한 암호화가 필요하고, 많은 개발자들에게 쉽지 않은 방법이었습니다. 이러한 문제를 해결하기 위해 OAuth 2.0이 2012년 10월에 출시되었습니다.

> 인터넷 표준 인증 방식으로, 애플리케이션 간 회원 정보를 안전하게 공유할 수 있는 방법입니다.

## OAuth 1.0 과 OAuth 2.0 차이점

- OAuth 2.0은 SSL을 사용하여 인증 과정을 간소화합니다.
- OAuth 2.0에서는 Signature가 필요하지 않습니다.
- OAuth 1.0은 매번 API 호출 시 두 개의 보안 토큰이 필요하지만, OAuth 2.0은 하나의 토큰만으로 인증이 가능합니다.

### OAuth 1.0
- **Transport-independent**: 보안이 HTTPS/TLS로 위임됩니다.
- 카카오, 트위터, 페이스북 등이 지원합니다.

### OAuth 2.0
- **Bearer Tokens** 중심: 사용이 쉽지만 보안에 취약할 수 있습니다.
- **범용성**: OAuth 1.0은 웹에서만 사용 가능하나, OAuth 2.0은 웹이 아닌 곳에서도 사용 가능합니다.
- **용도의 구분**: 리소스 요청에 대한 핸들링이 가능하고, 사용자마다 필요한 인증을 처리할 수 있습니다.

1. 클라이언트 애플리케이션 제공자 (구글, 트위터, 카카오, 네이버)
2. 클라이언트 애플리케이션은 "클라이언트 시크릿"을 요청합니다.
3. 잘못된 요청은 리젝 처리됩니다.
