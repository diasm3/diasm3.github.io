## PUT과 PATCH

### 개요
- **PUT**: 자원의 전체 교체를 수행하는 HTTP 메서드입니다. 자원을 교체할 때 모든 필드가 필요하며, 만약 일부 필드만 전달된다면 나머지 필드는 Null 또는 초기값으로 설정됩니다.
- **PATCH**: 자원의 부분 교체를 수행하는 HTTP 메서드입니다. 자원의 교체 시 일부 필드만 필요합니다.

## 멱등성
- 동일한 요청을 한 번 보내는 것과 여러 번 보내는 것이 같은 효과를 나타내며, 서버의 상태도 동일하게 유지될 때 해당 HTTP 메서드는 '멱등성'을 가진다고 말합니다.

| 멱등성                      | 비 멱등성              |
|---------------------------|--------------------|
| GET, HEAD, PUT, DELETE, OPTIONS, TRACE | POST, PATCH, CONNECT |
| 여러 번 보내도 같은 효과    | 여러 번 보내면 보낸 만큼 효과 |

## PUT 메서드
### 정의
PUT 메서드는 요청된 URI에 포함된 엔티티가 저장되기를 요청합니다. 만약 URI가 이미 존재하는 자원에 대해 참조한다면, 포함된 엔티티는 원본 서버에 있는 자원의 수정된 버전으로 간주되어야 합니다.

### 응답 코드
- 새 자원이 생성되면 201 (Created) 응답을 반환해야 하며,
- 기존 자원이 수정되면 200 (OK) 또는 204 (No Content) 응답 코드를 반환해야 합니다.

## PATCH 메서드
### 정의
PATCH 메서드는 PUT 메서드와 유사하지만, 요청된 내용이 URI로 식별되는 자원의 원본 버전과 원하는 콘텐츠 사이의 차이 목록을 포함합니다.

### 요구 사항
- 요청되는 엔티티는 변경에 필요한 충분한 정보를 포함해야 하며, 요청이 캐시를 통과할 경우 해당 캐시 항목은 제거되어야 합니다.
